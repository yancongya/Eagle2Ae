# 多面板配置系统需求文档

## 1. 项目背景

Eagle2Ae 扩展需要支持多个独立面板（主面板、导入面板、快速工具面板），每个面板需要：
- 独立保存自己的 UI 状态和配置
- 共享全局配置（如语言、主题、Eagle 服务器地址）
- 支持配置的导入/导出（预设功能）
- 在 Web Demo 模式下也能持久化存储配置

当前问题：
1. 新实现的 UI 面板组功能（uiSettings）未保存到预设 JSON 中
2. Web Demo 模式下无法持久化存储配置
3. 缺少多面板配置的统一管理机制

## 2. 核心需求

### 需求 2.1：多面板配置结构设计

**用户故事：** 作为开发者，我需要一个清晰的配置结构，能够区分全局配置和各面板独立配置

**验收标准：**
1. 配置 JSON 结构包含 `version`、`global`、`panels`、`shared`、`metadata` 五个顶层字段
2. `global` 字段存储所有面板共享的配置（语言、主题、Eagle 服务器地址等）
3. `panels` 字段包含各面板独立配置，以面板 ID 为键（main、import、quick）
4. `shared` 字段存储跨面板共享的数据（最近使用的文件夹、收藏夹等）
5. `metadata` 字段存储元数据（最后修改时间、最后活跃面板等）
6. 配置结构支持向后兼容旧版本预设文件

### 需求 2.2：UI 面板组配置持久化

**用户故事：** 作为用户，我希望我的 UI 面板组设置（显示/隐藏各个 UI 元素）能够保存到预设中，下次打开时自动恢复

**验收标准：**
1. uiSettings 配置保存到对应面板的配置中
2. uiSettings 包含所有 UI 元素的显示状态（theme、language、log、projectInfo、logPanel、header、fullscreen）
3. 切换面板时，自动加载该面板的 uiSettings
4. 导出预设时，包含所有面板的 uiSettings
5. 导入预设时，正确恢复各面板的 uiSettings

### 需求 2.3：Web Demo 模式配置持久化

**用户故事：** 作为 Web Demo 用户，我希望在浏览器中也能保存和读取配置，即使刷新页面也不会丢失设置

**验收标准：**
1. Demo 模式下，配置保存到 localStorage 或 IndexedDB
2. Demo 模式下，支持导出配置为 JSON 文件下载
3. Demo 模式下，支持从本地 JSON 文件导入配置
4. Demo 模式下，配置结构与 CEP 扩展模式完全一致
5. Demo 模式下，提供"重置为默认配置"功能

### 需求 2.4：面板 ID 识别机制

**用户故事：** 作为系统，我需要准确识别当前运行的是哪个面板，以便加载正确的配置

**验收标准：**
1. CEP 模式下，通过 `csInterface.getExtensionId()` 获取面板 ID
2. Web Demo 模式下，通过 URL 参数（如 `?panel=import`）获取面板 ID
3. 如果无法获取面板 ID，默认使用 'main'
4. 面板 ID 保存到 metadata 中，记录最后活跃的面板
5. 提供 `getCurrentPanelId()` 统一接口

### 需求 2.5：配置同步机制

**用户故事：** 作为用户，当我在一个面板中修改全局配置时，其他打开的面板应该立即同步更新

**验收标准：**
1. CEP 模式下，使用 CEP 事件（`com.eagle.eagle2ae.configUpdated`）广播配置变更
2. 其他面板监听配置变更事件，自动重新加载配置
3. Web Demo 模式下，使用 `storage` 事件监听 localStorage 变化
4. 配置同步仅影响全局配置，不影响面板独立配置
5. 提供防抖机制，避免频繁同步

### 需求 2.6：配置迁移与兼容性

**用户故事：** 作为用户，升级到新版本后，我的旧配置应该自动迁移到新结构，不会丢失任何设置

**验收标准：**
1. 检测旧版本配置（无 version 字段或 version < 2.0）
2. 自动将旧配置迁移到新结构（根级别配置移到 panels.main）
3. 迁移后保存新配置，并设置 version = "2.0"
4. 迁移过程中不删除旧配置，保留备份
5. 提供迁移日志，记录迁移过程

### 需求 2.7：预设导入/导出增强

**用户故事：** 作为用户，我希望能够灵活地导入/导出配置，可以选择导出单个面板或全部面板的配置

**验收标准：**
1. 导出预设时，提供选项：导出全部配置 / 仅导出当前面板配置
2. 导入预设时，提供选项：应用到所有面板 / 仅应用到当前面板
3. 预设文件包含版本号和导出时间戳
4. 预设文件支持压缩（可选）
5. Web Demo 模式下，导出为浏览器下载，导入通过文件选择器

### 需求 2.8：配置作用域管理

**用户故事：** 作为开发者，我需要明确定义哪些配置是全局的，哪些是面板独立的

**验收标准：**
1. 定义配置作用域常量（GLOBAL_SCOPE、PANEL_SCOPE、SHARED_SCOPE）
2. 语言、主题、Eagle 服务器地址属于全局作用域
3. 导入模式、导出设置、UI 面板组设置属于面板作用域
4. 最近使用的文件夹、收藏夹属于共享作用域
5. 提供配置作用域查询接口

### 需求 2.9：SettingsManager 改造

**用户故事：** 作为开发者，我需要改造现有的 SettingsManager，使其支持多面板配置管理

**验收标准：**
1. 添加 `getCurrentPanelId()` 方法
2. 添加 `getPanelConfig(panelId)` 方法
3. 添加 `updatePanelConfig(panelId, config)` 方法
4. 添加 `getGlobalConfig()` 方法
5. 添加 `updateGlobalConfig(config)` 方法
6. 添加 `getSharedConfig()` 方法
7. 添加 `migrateOldConfig()` 方法
8. 修改 `loadSettings()` 支持面板 ID 参数
9. 修改 `saveSettings()` 支持面板 ID 参数
10. 保持向后兼容，不破坏现有 API

### 需求 2.10：Demo 模式存储适配器

**用户故事：** 作为开发者，我需要一个存储适配器，统一处理 CEP 模式和 Demo 模式的配置存储

**验收标准：**
1. 创建 `StorageAdapter` 接口，定义 `load()`、`save()`、`export()`、`import()` 方法
2. 实现 `CEPStorageAdapter`，使用 localStorage + 文件系统
3. 实现 `DemoStorageAdapter`，使用 localStorage + 浏览器下载/上传
4. SettingsManager 根据运行环境自动选择适配器
5. 两种适配器的配置格式完全一致

## 3. 非功能需求

### 需求 3.1：性能要求
1. 配置加载时间 < 100ms
2. 配置保存时间 < 50ms
3. 配置同步延迟 < 200ms
4. 使用配置缓存，避免频繁读取存储

### 需求 3.2：可靠性要求
1. 配置保存失败时，不影响当前运行状态
2. 配置迁移失败时，回退到旧配置
3. 配置验证失败时，使用默认配置
4. 提供配置备份机制

### 需求 3.3：可维护性要求
1. 配置结构清晰，易于理解
2. 代码模块化，职责分离
3. 提供详细的日志记录
4. 提供配置调试工具

## 4. 技术约束

1. 必须兼容现有的 SettingsManager API
2. 必须支持 CEP 扩展和 Web Demo 两种运行模式
3. 配置文件格式为 JSON
4. 使用 localStorage 作为主要存储方式
5. CEP 模式下可选使用文件系统存储

## 5. 验收测试场景

### 场景 5.1：首次使用
1. 用户首次打开扩展
2. 系统加载默认配置
3. 用户修改部分设置
4. 配置正确保存

### 场景 5.2：多面板切换
1. 用户打开主面板，修改 UI 设置
2. 用户打开导入面板，UI 设置独立
3. 切换回主面板，UI 设置正确恢复

### 场景 5.3：全局配置同步
1. 用户在主面板修改语言为英文
2. 导入面板自动同步为英文
3. 快速工具面板自动同步为英文

### 场景 5.4：配置导入/导出
1. 用户导出当前配置为 JSON 文件
2. 用户重置配置
3. 用户导入之前的 JSON 文件
4. 所有设置正确恢复

### 场景 5.5：版本升级
1. 用户使用旧版本保存了配置
2. 用户升级到新版本
3. 系统自动迁移配置
4. 所有设置正确保留

### 场景 5.6：Demo 模式
1. 用户在浏览器中打开 Demo
2. 用户修改设置
3. 用户刷新页面
4. 设置正确保留
